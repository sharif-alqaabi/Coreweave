Helix: how the loop runs, what decides what ships, and what checks the survivors

One scout proposes, one critic judges, three architects rewrite the critic's rulebook. Each rewrite is promoted on training data and then checked on data it never saw. The check is the point. After that, TypeSafe checks every survivor against the rest of OSDR and links every finding to the papers that support or contradict it.

Scout
Qwen 235B. Reads a code-made summary of the table, never the raw rows. Prompt fixed.
Critic
Qwen 235B, different prompt. Sees one lead, the real numbers code attached, and the rulebook. One model, run once per lead per rulebook.
Architects
Qwen, DeepSeek, ARIA. Equal contestants. Each turns the misses into a patch; the tournament picks by score.
Jury
DeepSeek, gpt-oss, Kimi. Made the labels once. Separate from the critic on purpose.
TypeSafe
Jev, a System One model: typed answers and probabilities, no prose. Scores study comparability, reranks passages, types finding–passage and finding–finding pairs. ~10,000 judgments in 90 s; every threshold is code.
